# Author requirements for the report (v5)

**Source:** the author's requirement list ("Yêu cầu", items 1–21), item 22 added 2026-10-08. Numbering kept so
items can be cited as "AR n". These rules bind every chapter; where a rubric or format rule differs, the
resolution is stated in the item. Checked per chapter in Step C and again in the final review pass.

| AR | Rule | Check |
|---|---|---|
| 1 | Figures and tables are numbered with integers, consecutively from the start of the report ("Figure 12", never "Figure 3.2"). | Number scan |
| 2 | **Pipeline placement — the source sentence is incomplete ("phần pipeline thông thường sẽ đặt ở …").** Proposed from both samples: the research-framework figure closes Chapter 1 (Section 1.6); the technical pipeline figure opens Chapter 2 right after the data section, and each following section describes one block. *Awaiting author confirmation.* | Fig 2 in 1.6, Fig 5 in 2.2 |
| 3 | No appendix and no source-code link. | Search "Appendix", "github" |
| 4 | Remove v4 Section 3.6 and v4 Table 14 (objectives and requirements achieved). Rubric criterion 5 is met instead by naming the objective at the start of each Chapter 3 section and closing each objective in Chapter 5 (see `RUBRIC_MAP.md`). | No objectives table |
| 5 | The title is exactly the registered one: "Unsupervised Epileptic Seizure Temporal Localization in Scalp EEG using Graph Autoencoder and Change Point Detection". | Title page |
| 6 | Every equation can be pasted into Word: one equation per fenced block in Word-compatible LaTeX (Insert → Equation → LaTeX), numbered (1), (2), … at the right, followed by a "where …" line defining every symbol. No markdown-only math. | Paste test on one equation |
| 7 | No "Structure of the report" section (v4 1.7) and no roadmap paragraph opening a chapter (also a guide rule). | Search "This chapter" openings |
| 8 | The report shows novelty, the research gap it closes (from prior papers) and the practical problem it addresses: gap synthesised at the end of Section 1.2, contributions in 1.3, each contribution answered by a result in Chapter 3 and weighed in Chapter 4. | Gap → contribution → result trace |
| 9 | Citations are numeric [n]. Each chapter file ends with a table `[n] → DOI` (or URL when no DOI exists) taken from the verified reference sheet; the author inserts by DOI in Zotero, which renumbers globally. Chapters are written out of order (2, 3, 4, 1, 5), so [n] in a chapter file is a local placeholder. | DOI table complete |
| 10 | No internal terms the committee cannot know: no experiment, phase, look, tier, lever, tag, seed-file or code names (E1–E23, P1–P3, X1, A4/A5, L1/L2/L3, tier 2, T-A, …), no repository paths. Translations in HANDOFF_REPORT section 6. | Regex scan |
| 11 | Every clinical, signal-processing, machine-learning or statistical term is explained in one plain sentence before or at first use (Tri's pattern: what it is → what it does → why it matters here). | Glossary pass by a non-expert reader |
| 12 | Every number is read from the numbers pack or the record and labelled with its evaluation: held-out evaluation vs final system vs external; seed 42 vs 4-seed mean ± SD; pooled vs subject-mean. Never mix them in one sentence without labels. | `xanh` cross-check per chapter |
| 13 | Headings are uniform: sentence case, numbered to at most three levels (1.1.1), noun-phrase titles, same wording for the same concept across chapters. | Heading list |
| 14 | Cite where a claim comes from a paper (dataset, method, external number, clinical fact); do not cite own results or common knowledge. | Citation per external claim |
| 15 | Figures from other papers are allowed with the citation in the caption ("Figure n: Title [n]"), mainly in Chapter 1 (background) and Chapter 2 (methods not drawn here). Every borrowed figure is checked in the source PDF first. Candidates in `REPORT_BLUEPRINT_v5.md`. | Source PDF checked |
| 16 | Information flows top to bottom: no term, number, dataset or component appears before it is introduced; each section answers the question the previous one raised. Transitions are optional; order is not. | Forward-reference scan |
| 17 | IELTS-style coherence: one central idea per paragraph, opened by a topic sentence; clear referencing; varied but precise vocabulary; no repetition of the same point. | Paragraph read |
| 18 | Deployment decision matrix: criteria must be the ones that actually decide the choice. Resolution: `Report format.md` requires the decision matrix to show how global, economic, environmental and societal factors shaped the design (rubric criterion 4, 10 points), so each impact category is expressed as a concrete, decision-driving criterion (data protection, cost to the hospital, hardware and energy, processing time, maintenance and scaling) — Tri does the same. The broader impact discussion stays in Chapter 4's impact section (criterion 7). | Criteria list in Table 8 |
| 19 | Each chapter is written once, after all its inputs are checked; no later rewrites unless a fact changes. | — |
| 20 | Application content that the rebuild will change (old pipeline, old processing time, memory, old detection numbers, old screens) is removed now; parts the rebuild does not change (deployment decision, local and label-free operation, guards) are kept. Fallback after 12/10: HANDOFF_REPORT section 0. | No old app numbers |
| 21 | Researcher voice, not an audit log: Methods describe the final system only; Results report what that system produced (counts such as TP/FN/FP may be shown); the reason for a chosen value may be one clause ("chosen on the training and validation patients, where …"). Designs that were tried and did not help go to Discussion as evidence of limits. No narration of the process ("first we tried …, then …"). Select what is worth reporting; do not omit an unfavourable result of the final system. | Process-verb scan |
| 22 | Captions are short titles (about 3–8 words), never a sentence or paragraph; explanation goes in the text. No size or layout attributes. In the chapter files a figure is a placeholder line `[Figure n: Title]` at its insertion point (caption below the figure); a table is given in full with `Table n: Title` above it. The author inserts the images. | Caption length scan |
