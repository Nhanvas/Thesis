(c) Filtering convention: offline committed arrays vs Scope T (from the code)
====================================================================================================

Offline committed arrays (results/phaseB/tier2/ens_test_tf/components/, and the
ens_seed42_{subj}_{inter,ictal}.npy ensembles behind them) trace back to
data/processed/{subj}_interictal.npy / {subj}_ictal.npy, written by
src/dataprep/preprocessing.py `write_windows()`:

    window = filter_window(raw, start, end)   # per WINDOW, one 4 s window + FILTER_PAD (3 s)
                                               # padding each side, sosfiltfilt+filtfilt,
                                               # re-read from `raw` via raw.get_data(start,stop)
                                               # for EVERY window independently

Scope T (src/continuous_eval.py `filter_file()`) filters the WHOLE recording in one
sosfiltfilt/filtfilt pass (matching the application's own convention, per Amendment-driving
G1 work) -- NOT per-window-with-padding. This is a real, confirmed algorithmic difference
between what produced the offline committed arrays and what Scope T's own windows are filtered
with. (Scope T's ARTIFACT MASK, separately, already uses the per-window filter_window
convention -- see continuous_eval.compute_artifact_flags -- only the SCORED SIGNAL itself
differs in filtering method from the offline arrays.)
